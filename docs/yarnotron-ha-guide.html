Yarnotron as a Home Assistant voice agent

A child talks to a Home Assistant voice satellite. Assist hears them, Yarnotron makes up the story, the safety review checks every sentence, and parents get a phone alert when something is flagged.

What you get

  • A conversation agent named Yarnotron that you pick in any Assist pipeline. Replies stream sentence by sentence, so speech can start before the story is finished.
  • The same safety rules. Every reply is still reviewed. After the strike limit the session ends and the child cannot restart it. Only a parent can, with a button or a service call.
  • Parent alerts that actually arrive. The original only marked an alert as sent. Now a flagged turn raises an event you can send to a phone.
  • Dashboard controls: a Storytime on/off switch, strike count, unreviewed events, model-server health and review/release services.

Your setup

You run Home Assistant OS locally and use Home Assistant Cloud. Home Assistant OS is a poor home for the story model, so the Yarnotron backend and Ollama stay on your Mac or GPU PC. The integration on the HA box talks to it over your home network with a secret token. Home Assistant Cloud is not needed for any of that. It only matters for speech (see the privacy note in Implementation).

Decide this before you start: where the child's voice goes

Home Assistant Cloud speech-to-text and text-to-speech send audio to a third-party service. Yarnotron was built to keep everything local. For a child's voice, install the free Whisper and Piper add-ons in Home Assistant and use those in the Yarnotron pipeline. Cloud speech still works if you prefer it.

Structure

One turn, step by step

  1. The satellite hears the wake word and Assist turns speech into text.
  2. The agent checks the Storytime switch, then the lock. Help, repeat, sleep and stop are answered locally.
  3. Otherwise the agent opens or reuses a Yarnotron session and streams the turn. Each sentence arrives only after the safety review releases it.
  4. Assist speaks sentences as they arrive and, by default, keeps listening for the child's reply.
  5. If the turn was flagged, the coordinator polls again about six seconds later, because the model's review finishes just after the reply. A new event raises the safety_alert event once.

Capabilities and changes

Kept as it was

  • Story building, memory and undo
  • Layered safety review and strike counting
  • Parent dashboard in the browser
  • Image approval queue
  • All data stored locally

Replaced by Home Assistant

  • Microphone, wake word and speaker
  • Speech-to-text and text-to-speech
  • Parent alert delivery
  • Operating hours (use the Storytime switch with a schedule)

Not ported

  • Barge-in (interrupting the story mid-sentence)
  • The space-friend howl
  • The custom wake word "interpreter" works only if you train it. Built-in wake words or the satellite's button work now.

Services

All are under yarnotron. and take an optional config_entry_id (only needed with more than one child): review_safety_event, release_safety_event, start_new_session, end_session, set_story, list_stories and export_story. Reviews record which Home Assistant user acted.

Implementation guide

About 30 minutes. You need the backend machine, your Home Assistant, and a phone with the Home Assistant app for alerts.

  1. Make a token

    On the backend machine, create a long random secret. You will paste it twice.

    openssl rand -hex 24
  2. Start the backend where Ollama runs

    Either option works. Set the token first, then bind to the network. The start script warns if you bind to the network without one.

    Directly on a Mac or PC:

    export YARNOTRON_API_TOKEN=<your token>
python3 scripts/start_yarnotron.py --host 0.0.0.0 --no-reload

    Or with Docker (put the token in .env, see .env.example):

    cp .env.example .env
docker compose up -d --build

    Check it from another computer on your network: http://<backend-ip>:8989/health should answer. Give the backend machine a fixed address or a DHCP reservation so Home Assistant can always find it.

  3. Install the integration

    With HACS: add the Yarnotron-HA repository as a custom repository (category Integration), install, then restart Home Assistant. Without HACS: copy custom_components/yarnotron into your Home Assistant /config/custom_components/ folder and restart.

  4. Add it

    Settings → Devices & services → Add integration → Yarnotron. Enter the backend address (for example 192.168.1.20:8989), the token, and a child ID. Keep local_child for one child. Errors are specific: wrong token, unreachable, or a backend too old to have /v1/status.

  5. Choose local speech

    Install the Whisper and Piper add-ons (Settings → Add-ons) and let them be discovered. You can run them on the AI machine instead if your HA box is small. This keeps the child's voice off the internet.

  6. Create a dedicated Assist pipeline

    Settings → Voice assistants → Add assistant. Set Conversation agent to Yarnotron, speech-to-text to Whisper, text-to-speech to Piper, and language to English.

    Turn "Prefer handling commands locally" off

    If it is on, a child could say "turn off the lights" and Home Assistant would do it. Yarnotron's agent cannot control devices, so with this off the child's words only ever reach the storyteller. Keep a separate pipeline, and do not expose devices to it.

  7. Assign it to a satellite

    Open the voice satellite's device page and set its pipeline to the new one. Use a built-in wake word, or the satellite's button. Training "interpreter" as a custom wake word is optional.

  8. Test without a microphone

    From the Assist dialog, pick the Yarnotron pipeline and type: "tell me a story about a dragon". A reply and a new session appear on the Yarnotron dashboard at http://<backend-ip>:8989/dashboard.

  9. Send alerts to your phone

    Settings → Automations → Create → Use blueprint → Yarnotron safety alert. Choose the alert entity, which kinds to send (blocked and session ended by default) and an action such as notify.mobile_app_your_phone. Message templates can use alert_type, categories, parent_note and severity.

    action: notify.mobile_app_your_phone
data:
  title: Yarnotron
  message: "{{ alert_type }}: {{ parent_note }}"
  10. Add a parent card

    Put the Storytime switch, session-locked sensor, strikes and the two buttons on a dashboard. Use a schedule helper with an automation on the switch for bedtime and quiet hours.

Options

Status refresh interval (default 30 s, 10 to 600)
How often Home Assistant checks the backend for new events.
New session after idle (default 30 min)
A long pause starts a fresh session on the next chat.
Keep listening after each reply (default on)
The child can answer without repeating the wake word.
Include what the child said in alerts (default off)
When on, alerts carry an excerpt, and Home Assistant stores it in its database and history. Leave it off unless you want it.

Security notes

  • Use the token on any machine that is reachable from your network. Without it, anyone on the network can read stories and use parent controls.
  • /health, /dashboard and /media are intentionally open so the page and generated images can load. They show no story text.
  • Parent controls in Home Assistant are not limited per user. Do not give the child a Home Assistant login.
  • Keep the backend on your home network. Do not forward the port to the internet.

User guide

For the child

Say the wake word and ask for a story. After each answer the speaker keeps listening, so talk back whenever you like. Try:

"Tell me a story about a dragon""Add a new character""Change the castle to a treehouse""Read me a recap""Undo the last change""Repeat that""Help"
"Stop listening" or "go to sleep"
The speaker stops listening until the next wake word. The story is kept.
"Stop" (ending the story)
Ends this story session. The next request starts a new one.
If it says storytime is resting
A grown-up turned storytime off. Try again later.
If it says it needs a grown-up
The session ended. Ask a parent to start a new one.

For parents

When an alert arrives

  1. Open the Yarnotron dashboard (device page → Visit) and find the event. Alerts show the category and note, not the words, unless you enabled transcripts.
  2. Mark it reviewed with yarnotron.review_safety_event or on the dashboard. The unreviewed counter goes down.
  3. If a block was a mistake, yarnotron.release_safety_event lets that turn through. Only blocked turns can be released.

When a session locks

After the strike limit (5 by default) the session ends and Session locked turns on. The child's requests get a gentle "ask a grown-up" and nothing reaches the backend. This holds across Home Assistant restarts. Press Start new session (or call yarnotron.start_new_session) when you are ready.

Everyday controls

  • Storytime switch for operating hours. Pair it with a schedule or presence automation.
  • Choose story (yarnotron.set_story) pins the story the next session continues. Use list_stories to see ids and export_story for a Markdown copy.
  • Model server sensor off means Ollama is down. The child hears a short apology instead of silence.

Troubleshooting

Re-authentication prompt appears
The token changed. Enter the new one in the prompt.
Entities show unavailable
Home Assistant cannot reach the backend. Check the machine is awake, the address has not changed and the firewall allows port 8989. They recover on their own.
The agent says it is having trouble
The backend or Ollama is down. Check the model-server sensor.
Satellite never answers with the story
Confirm the satellite uses the Yarnotron pipeline and that the pipeline's agent is Yarnotron.

Power control: launch, shut down, status

Optional. This section is for a setup where the backend runs directly on a Mac that may sleep. If the backend runs as an always-on container (for example on the Mac Studio hub), leave the supervisor address empty and keep voice launch and shutdown off: the container restarts by itself. Where it applies: the backend lives on a Mac, which may be asleep or have nothing running. A small supervisor runs on the Mac all the time (a launchd job, Python standard library only). Home Assistant asks it to check, start and stop Ollama, Whisper and the Yarnotron backend. Setup steps are in docs/mac-power-control.md.

SayWhat happens
"Launch Yarnotron"If the Mac does not answer and you gave its MAC address, a wake-up packet is sent. Then each Mac process is checked in dependency order (Ollama, Whisper, backend). Anything not answering is started, and a hung copy holding its port is restarted. A backend left refusing stories by an earlier shutdown is told to resume.
"Shut down Yarnotron"It asks first: "say yes, shut down". On yes, the open session is ended, the backend refuses new turns, waits for running turns and deferred safety reviews, ends open sessions, folds the database log into the file and reports the story it saved. Only then are the processes stopped, in reverse order. If saving fails or work is unfinished, nothing is stopped.
"Yarnotron status"Speaks every component on both sides with its state. Home Assistant: integration, voice agent, backend link, Piper and Whisper entities, voice satellites, story session. Mac: supervisor, Ollama, Whisper, backend.

When something does not behave

The spoken answer is one plain sentence naming the cause, for example "Whisper started and then quit straight away (exit code 3)". The full account goes to a Home Assistant notification: what was observed, the last lines of that process's log, and what to try. The same details are in the status service's response and the Mac services sensor. Distinguished causes include: command not found, quit at startup, running but never answering, port held by an unknown process (never killed), supervisor not running versus Mac asleep, wrong token, backend busy, and a process that came back after being stopped.

Also available

  • Buttons Launch Yarnotron and Shut down Yarnotron, a Host services sensor and a Host supervisor sensor.
  • Services yarnotron.launch, yarnotron.shutdown (with force) and yarnotron.status, which return their result for automations. An event yarnotron_power_finished fires when a launch or shutdown ends.
  • Options: supervisor address and token, the Mac's MAC address, and a switch that turns voice launch and shutdown off (status still works), so a child cannot power it down.

Limits. A MacBook that sleeps cannot run anything until woken, and Wake-on-LAN on a MacBook over Wi-Fi is unreliable, so keep it awake on power. The launchd agent runs only while you are logged in. The supervisor can stop only processes it can find by their port. Ollama's menu-bar app may restart the server after a stop; the status check reports that rather than hiding it.

Letting a child pause mid-sentence

Assist decides a child has finished when it hears about 0.7 seconds of silence. Children pause to think, so sentences get cut off. In the Yarnotron options, pick the voice satellites' Finished speaking detection selects and choose Relaxed (about 1.25 seconds). Yarnotron sets them when Home Assistant starts. The backend also holds a sentence that stops on a word like "and" or "the", answers with a short nod, and joins it to the next thing the child says.

Verification and limits

Checked

  • 313 backend tests pass, including auth on every /v1 route family, the graceful shutdown drain, and the Mac supervisor run against real throwaway processes (start order, exit-at-startup, never-answers, hung port holder, refusal to kill an unknown process, save-before-stop).
  • 92 integration tests pass against Home Assistant 2026.2.3 with a fake backend over real HTTP: setup, reauth, alert de-duplication, transcript privacy, streaming, the strike lock holding until a parent acts, idle expiry, services, the blueprint firing, and the voice launch, shutdown (with confirmation) and status paths with success, failure and unreachable-Mac cases.
  • Two key tests were confirmed to fail when the lock check or the transcript privacy rule was removed.
  • The backend's install and start steps were run by hand outside Docker with no audio libraries.

Not checked

  • The Docker image has not been built, because there was no Docker daemon. Treat the first build as a test.
  • No real voice satellite, wake word or speaker was used. Streaming speech timing is untested on hardware.
  • Only Home Assistant 2026.2 was tested. hacs.json asks for 2026.2.0 or newer.
  • Home Assistant Cloud speech was not tested; local Whisper and Piper are the recommended path.
  • The Mac supervisor has never run on a real Mac: launchd install, lsof, uv start-up, Ollama's menu-bar app and Wake-on-LAN are untested. Process control was tested on Linux.
